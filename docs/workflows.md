# Workflows and tools

The setup established Roblox teams use, and how this template applies it.
Researched 2026-11-16 from Roblox's docs, the tools' own repos and the
DevForum. Versions are the pins in `rokit.toml` and `wally.toml`.

## Code quality

`tools/check.cmd` (Windows) or `tools/check.sh` (macOS, Linux) runs what CI
runs (`.github/workflows/check.yml`, on every push to `main` and every pull
request): format, lint, types, build and the headless specs. Run it before
committing; `fix` as the argument formats `src/` and `tests/` first.

| Tool | Pin | Does |
|---|---|---|
| [Rojo](https://rojo.space) | `rojo-rbx/rojo@7.7.1` | Syncs `src/` into Studio; builds the place; writes `sourcemap.json` |
| [StyLua](https://github.com/JohnnyMorganz/StyLua) | `JohnnyMorganz/StyLua@2.6.0` | Formatting (`stylua.toml`: tabs, 120 columns, double quotes, sorted requires) |
| [selene](https://github.com/Kampfkarren/selene) | `Kampfkarren/selene@0.32.0` | Lint, Roblox standard library (`selene.toml`) |
| [luau-lsp](https://github.com/JohnnyMorganz/luau-lsp) | `JohnnyMorganz/luau-lsp@1.70.1` | Type check (`luau-lsp analyze`) against Roblox's API definitions; editors use it as a language server |
| [Wally](https://wally.run) | `UpliftGames/wally@0.3.2` | Packages (below) |
| [wally-package-types](https://github.com/JohnnyMorganz/wally-package-types) | `JohnnyMorganz/wally-package-types@1.7.0` | Makes package types visible to luau-lsp |
| [Lune](https://github.com/lune-org/lune) | `lune-org/lune@0.11.1` | Runs Luau outside Roblox: build and Open Cloud scripts, and headless tests (below) |

All code type-checks in strict mode (`.luaurc`), no `--!strict` line
needed. The type check uses the
`None` security level definitions, the right ones for game code.
`src/shared/assets.luau` (generated by Asphalt) is skipped by all three
checks.

## Packages

Wally is still the community default; Roblox's own docs name it, and Roblox
publishes its official Jest and React packages there. `wally.toml` lists
maintained picks, commented out:

| Need | Package | Notes |
|---|---|---|
| Player data | `lm-loleris/profilestore` 1.0.3 | Session locking. Successor to ProfileService (don't use that) |
| Cleanup | `sleitnick/trove` 1.8.0 | Or Janitor; pick one |
| Events | `sleitnick/signal` 2.0.3 | |
| Async | `evaera/promise` 4.0.0 | Roblox also publishes `roblox/promise` |
| UI | `roblox/react` + `roblox/react-roblox` 17.3.13 | Roblox's own; the old jsdotlua fork is behind. Vide (`centau/vide`) is a lighter reactive option |
| Networking | [Blink](https://github.com/1Axen/blink) or [Zap](https://github.com/red-blox/zap) | Generate typed, packed remotes from a schema file. Rokit tools, not Wally packages |
| ECS | `ukendio/jecs` | Only if the game is built around an ECS |

Uncomment what's needed and run `wally install`. Packages land in
`Packages/` and `ServerPackages/` (gitignored; commit `wally.lock`), which
Rojo maps to `ReplicatedStorage.Packages` and
`ServerScriptService.ServerPackages`.

Skip: Knit (archived), ProfileService (superseded), Matter (stale since
2024), TestEZ and the jsdotlua forks (replaced by Roblox's own Jest and
React), Aftman and Foreman (Rokit replaces them), Mantle (unmaintained).
pesde works but isn't the default.

## Project layout

This template is **partially managed**, the layout Roblox recommends for
most teams using Git: code and config live in Git and sync with Rojo; the
world (parts, meshes, terrain, lighting) lives in the place. Rojo can't
live-sync `MeshPart.MeshId`, terrain or unions, which is why the world stays
in Studio. Bring world pieces into files later with `rojo syncback` if
needed.

With several people: don't all Rojo-sync into one Team Create place. Each
person syncs into their own copy; changes meet in Git.

## Environments and publishing

Roblox recommends **one experience per environment** (dev, staging,
production) under the same community, because data stores, secrets and
settings belong to the experience, not the place. Keep each environment's
IDs and keys in your secrets manager (or one `.env` per environment).

Publishing a place from CI: Open Cloud's
[place publishing](https://create.roblox.com/docs/cloud/guides/usage-place-publishing)
(`PATCH https://apis.roblox.com/assets/v1/assets/{placeId}` with the place
file and `"published": true`), then
[`:restartServers`](https://create.roblox.com/docs/cloud/reference/features/universes)
to move live servers onto it. A curl or [Lune](https://github.com/lune-org/lune)
script is enough; Mantle is unmaintained and rbxcloud has been quiet since
2025. Not set up yet: it needs an experience per environment and a key with
**assets** write access to its places.

## Tests

Roblox's own [Jest](https://github.com/Roblox/jest-roblox) (`roblox/jest`
3.21.0, a Wally dev dependency) is the standard. It runs only inside Roblox,
so headless runs go through Open Cloud's
[Luau Execution API](https://create.roblox.com/docs/cloud/reference/features/luau-execution):
Roblox's [rocale-cli](https://github.com/Roblox/rocale-cli) (0.1.3, early)
builds the Rojo project, uploads it to a test place and runs the specs
there. Limits: 5 minutes per run, 5 runs started per minute. Not set up
yet: it needs a test experience and a key limited to it, with assets write
(to upload the test place) and `universe.place.luau-execution-session:write`. Until then, test by
playtesting through the Studio MCP.

**Set up in this template: headless specs with Lune.** `tools/test.cmd` /
`tools/test.sh` (and `check`, and CI) run every `tests/*Spec.luau` on your
own machine in well under a second, with no Roblox. `tools/lune/specs.luau`
builds a read-only instance tree from `default.project.json`, so specs
`require` modules exactly as in Studio. It suits pure logic: economy, data,
rules, simulations. Anything that needs real instances, physics or rendering
errors there; playtest that through the Studio MCP instead. Keep game logic
in pure shared modules so most of it can be specced. `tests/Expect.luau` is a
small assertion helper and `tests/NumberFormatSpec.luau` the example.
`tools/test.cmd Save Shop` runs only specs whose names contain those words.

## Art: Blender to Roblox

Install Blender (5.x): `winget install BlenderFoundation.Blender` on
Windows, or from blender.org. On Windows `tools\find-blender.cmd` finds the
newest installed copy and `tools\blender.cmd` runs it. On macOS, start
Blender with `--online-mode` yourself and point the `Blender` entry in
`.mcp.json` at `blender-mcp`.

**Export.** glTF (`.glb`) needs no scale settings. For FBX, Roblox
documents: Path Mode *Copy* with *Embed Textures*, Apply Scalings *FBX Unit
Scale*, *Add Leaf Bones* off, *Bake Animation* only when animated.

**Roblox's mesh limits** ([specifications](https://create.roblox.com/docs/art/modeling/specifications)):

- 20,000 triangles per mesh, one material per mesh, at most 4 bone
  influences per vertex.
- Textures render up to 4096 px, but use 1024 or less for PBR (phones).
  Normal maps are OpenGL tangent space.
- `SurfaceAppearance` takes colour, normal, roughness, metalness and
  emissive maps.
- Faces are one-sided: a face wound the wrong way is invisible from outside.

**Getting it in.**

- *Static meshes and textures:* put the `.glb` and its texture PNGs in
  `assets/` and run `tools/assets.cmd` (or `.sh`). Asphalt uploads a `.glb` as a Model.
  Load it with `InsertService:LoadAsset(id)` and take its MeshPart, then
  set the texture through a `SurfaceAppearance`. The web upload has no
  import settings.
- *Rigs, skinned meshes and anything needing import settings:* use Studio's
  [3D Importer](https://create.roblox.com/docs/studio/importer) (R15 or
  Custom rigs; OBJ is single-mesh only). It uploads as whoever is signed in
  to Studio, so ask the user before using it (AGENTS.md, rule 7).
- *Roblox's [Blender plugin](https://github.com/Roblox/roblox-blender-plugin)*
  (1.0.5) uploads straight from Blender after an OAuth sign-in. It's for
  people working by hand; agents use `tools/assets.cmd`.

**Animation.**

- Studio's Animation Editor imports FBX animations (*Import From FBX
  Animation*).
- The Studio MCP's `generate_animation` makes R15 clips of up to 10 s.
- Mixamo clips need retargeting to R15 in Blender first; there is no
  official route.
- Animations upload only as `.rbxm`/`.rbxmx`. Save the KeyframeSequence
  from Studio into `assets/`; Asphalt detects it and uploads it as an
  Animation.

### Blender MCP

`.mcp.json` runs Blender Lab's official server
([projects.blender.org/lab/blender_mcp](https://projects.blender.org/lab/blender_mcp),
v1.0.3, GPL-3.0) through `tools\blender-mcp.cmd`. It can:

- run Python in a running Blender, or in a background Blender it starts
  itself;
- summarise scenes and .blend files;
- take screenshots;
- look up Blender's Python API and manual.

One-time setup:

1. Blender 5.1 or newer. In Edit → Preferences → Get Extensions →
   Repositories, add `https://lab.blender.org/`. Then install and enable
   the **MCP** add-on.
2. Install the server:
   `uv tool install "git+https://projects.blender.org/lab/blender_mcp.git@v1.0.3#subdirectory=mcp"`.
   This puts `blender-mcp` in `%USERPROFILE%\.local\bin`.
3. Start Blender with `tools\blender.cmd`. It runs with online access on;
   the add-on only opens its socket (port 9876) then.

Its code execution isn't sandboxed; it runs anything with your user's
rights.

`uvx blender-mcp` is a different, community server:
[ahujasid's](https://github.com/ahujasid/blender-mcp), now published as
`mcp-for-blender`. It adds Poly Haven, Sketchfab and Poly Pizza downloads,
and AI model generation (paid keys). It sends usage telemetry unless
`DISABLE_TELEMETRY=true`, and uses the same port, so run one or the other.

## Other MCP servers and AI tools

- **Studio MCP extras:**
  - `generate_mesh`, `generate_material`, `generate_animation`,
    `generate_avatar` and `generate_procedural_model`. Outputs are yours to
    use, but may not be unique.
  - `open_cloud_invoke`: Open Cloud calls through Studio without an API
    key, limited to the scopes and upload folders the user enables per
    experience.

  Both act as the signed-in Studio user, so for your own files keep using
  `tools/assets.cmd` (or `.sh`).
- **Roblox docs as Markdown:** append `.md` to any
  `create.roblox.com/docs/...` URL. The index is
  [`/docs/llms.txt`](https://create.roblox.com/docs/llms.txt). This beats
  any docs MCP.
- **[ElevenLabs](https://github.com/elevenlabs/elevenlabs-mcp)** (hosted
  MCP, OAuth): sound effects and voice. It has a free monthly allowance,
  but check the plan's licence before shipping its output (commercial use
  needs a paid plan).
- **Skipped:** community Roblox docs servers (the `.md` docs cover it), and
  Freesound or Sketchfab servers (community-only, with a different licence
  per file).

## In Studio

- **Profiling:** [MicroProfiler](https://create.roblox.com/docs/performance-optimization/microprofiler)
  (Ctrl+F6) for frame time,
  [Script Profiler](https://create.roblox.com/docs/studio/optimization/scriptprofiler)
  for Luau, and the
  [Developer Console](https://create.roblox.com/docs/studio/developer-console)
  (F9) for memory, network and errors in live servers.
- **Analytics:** `AnalyticsService` funnel, economy and custom events.
- **Live config:** [Configs](https://create.roblox.com/docs/production/configs)
  (`ConfigService`) for feature flags and tuning without a publish.
- **Untrusted models:** keep `ServerScriptService.LoadStringEnabled` off.
  Vet free models as in [asset-sources.md](asset-sources.md).
